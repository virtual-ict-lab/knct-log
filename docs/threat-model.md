# 脅威モデル（概要）

## サーバー（CF・学内）に見えるもの

- グループ ID、各メンバーのアカウント公開鍵（メンバー構成）、管理者が誰か
- レコードの種類・作成時刻・サイズ、blob のサイズ
- リアクション・返信の**宛先（投稿者）**と時刻（通知に使う）。どの投稿への反応かと内容は見えない
- アカウント文書の存在・更新時刻・登録されたパスキーの数と credential ID
- 招待トークンのハッシュ、通知の時間帯設定、Push 購読の endpoint

## 見えないもの

- 動画の中身、動画に重ねた文字、リアクション・返信の内容、グループ名、表示名、撮影時刻（すべてグループ鍵で暗号化）
- グループ鍵（各アカウントの X25519 公開鍵宛てに HPKE で包まれている）
- アカウントの秘密鍵（AMK で暗号化。AMK はパスキーの PRF 出力かリンクの乱数から導出した鍵で包まれている）

## 守れること

- サーバーやストレージが漏れても、動画は読めない。
- サーバーはレコードやアカウント文書を偽造できない（すべてアカウントの Ed25519 署名つき）。
- アカウント文書が漏れても、パスキー（とその生体認証・PIN）がなければ鍵は開けない。PRF 出力は 32 バイトの乱数相当なので総当たりできない。
- 退会したメンバーは、その後の投稿を読めない（鍵のローテーションとサーバー側のアクセス拒否）。
- 他人を勝手に削除することはできない（プロトコルに操作がない）。

## 守れないこと・割り切り

- 悪意のあるサーバーは、レコードを**隠す**（配らない）ことはできる。
- 招待リンクを手に入れた人は参加できる。リンクは直接渡し、不要になったら失効させる。
- 参加者には、現 epoch のそれまでの投稿も見える（退会がなければ epoch は変わらない）。
- `ts` は作成者の自己申告。導出の順序に影響するが、権限の範囲内でしか意味を持たない。
- パスキーを 1 つも登録していないアカウントは、その端末を失うと戻らない。設定画面からパスキーを追加しておく。
- パスキーと、それを同期しているアカウント（Google / Apple）を乗っ取られると、アカウントの鍵も取られる。
- 引き継ぎ用の QR を撮影された場合、期限（10 分）内なら別の端末に取り込まれる。使ったら消え、閉じると取り消す。
- 悪意のあるサーバーは、古いアカウント文書を配ることはできる（新しいパスキーが使えないだけで、鍵は守られる）。
- 端末上の AMK は IndexedDB に保存している。同じオリジンで任意のコードを実行できる攻撃者（XSS など）には取られうる。
- 同じアカウントの端末は同じ鍵を持つので、1 台だけを締め出す（失効する）ことはまだできない。
- 退会前に保存・共有された動画（Vlog を含む）は取り消せない。
